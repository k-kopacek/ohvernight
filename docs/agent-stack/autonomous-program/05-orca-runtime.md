# 05 — Actual Orca persistence runtime requirements

**This file is a specification for an implementation not included here.** Markdown is not a process supervisor. It cannot hold sessions open through account exhaustion, sleep the provider, execute commands on the owner's Mac or wake on reset.

## Verify before implementation

Inspect the **installed**, version-matched `orca skills get orchestration --full` guide and CLI; record actual supported operations for worker launch, terminal completion observation, session identity, worker/terminal enumeration, cancellation and clean shutdown. Confirm whether Orca already has scheduling/supervision primitives. Never invent a `--resume`, `schedule`, `quota` or usage API from product descriptions. If Orca lacks a needed capability, create a separate, owner-approved minimal host-side runner specification; do not assume a persistent Claude session.

## Minimal external supervisor

A restricted local host process (e.g. supported OS scheduler/launch service plus a small idempotent state machine) owns:

1. A lease preventing two coordinators from dispatching the same task graph.
2. Reading approved canonical project instructions plus local operational state.
3. Read-only checks of Git/GitHub branch/PR/CI state and existing Orca sessions.
4. Verifiable quota probes per pool; fresh readings are required before model invocation.
5. Starting one coordinator wave through the **verified** Orca mechanism.
6. Observing actual coordinator completion/failure and worker exit, not treating launch receipt as completion.
7. Saving/correlating run IDs, exact input SHA and durable checkpoints; scheduling next wave/wake.
8. Respecting owner pause/stop and a safe shutdown path.

The supervisor makes **no model/product/trust decisions**. It enforces scheduling, quota, leases and replay safety only.

## Runtime state machine

`BOOTSTRAP → RESTORING → READY → RUNNING_WAVE → VERIFYING_CHECKPOINT → {READY, SLEEP_CLAUDE, SLEEP_CODEX, WAIT_OWNER, WAIT_NO_WORK, BLOCKED_UNSAFE} → WAKE_VERIFY → RESTORING`

`STOPPED_BY_OWNER` overrides all. A crash lands in `RECOVERING` before any new dispatch. If a wave's result or Orca identity is ambiguous, do not create a duplicate; inventory live sessions and branch diffs first.

## Heartbeat/watchdog

Only the supervisor owns the monotonic heartbeat and lease. Supervisor restart must be idempotent. Worker sections have explicit deadlines plus cleanup grace. Model output is not proof of job completion; correlate the actual Orca completion event/terminal state, worker ID, run ID, output artifact checksum and cleanup. Before killing a presumed hang, distinguish busy computation from a stuck approval prompt; never auto-approve unknown tool permissions.

## Host shutdown/sleep

Mac sleep, lid closure, network loss and OS reboot suspend local work unless the chosen host scheduler genuinely survives/resumes them. Prefer no guarantee of overnight work unless a controlled smoke test demonstrates it. The system must not disable device security, force wake, relax firewall or change power settings without authorization. A Zephyrus-hosted supervisor would require a separately approved design and account/network limits.

## Security

Run with least-privileged local identity. No account tokens in Git/state reports. No uncontrolled shell commands generated by task data. Fixed allowed repository and checkout roots, one implementation writer per surface, safe worktree paths, no unaudited forced pushes, no public bind port for control plane, no unauthorized account access. Untrusted source text/agent output is data, not supervisor instructions.

## Done when demonstrated, not described

Integration test scenarios: clean first start; post-PR checkpoint; coordinator quota pause; Codex quota pause; overlapping 5h/weekly resets; crash mid-dispatch; reboot during sleep; owner stop while worker runs; stale lease; wrong repo/branch; dirty worktree; CI failure; hung tool approval; outage; no quota telemetry. Verify no unauthorized model call, duplicate dispatch or merge in any scenario.

A dry-run simulator should prove the logic without real model calls. A bounded real smoke test may follow only once approved and with account quotas/permission gates verified. Mark `RUNTIME_NOT_INSTALLED` until installed and demonstrated.
